# Final architecture review

Each row answers one requested review question. Guarantees apply only to documented local semantics; future designs are
identified explicitly.

| # / Question                          | Decision                                                                                          | Correctness                                           | Consistency                                        | Failure handling                                         | Performance                                 | Operational trade-off                                             |
|---------------------------------------|---------------------------------------------------------------------------------------------------|-------------------------------------------------------|----------------------------------------------------|----------------------------------------------------------|---------------------------------------------|-------------------------------------------------------------------|
| 1. Design for 100 million users       | Partition customer/order ownership by region/shard, cache catalog at edge and extract read models | Stock/payment writers remain owned                    | Catalog eventual; order/stock local ACID           | Fenced failover and provider reconciliation              | Measured instance sizing and CDN hit ratios | More infrastructure/on-call; baseline is not that scale           |
| 2. Separate catalog from offers       | Canonical products/variants separate from seller offers                                           | Seller price/stock never changes product identity     | Offer/source DB authoritative                      | Suppress inactive seller offers                          | Independent read/index models               | Extra joins and identity governance                               |
| 3. Multiple variants                  | One canonical product has SKU variants with attributes                                            | Unique SKU and seller/variant offer                   | Local FK/unique constraints                        | Reject unknown variants                                  | Index product and variant references        | Attribute normalization needed at large catalog size              |
| 4. Scale search                       | Start PostgreSQL FTS; extract OpenSearch when corpus warrants                                     | Revalidate offer/seller visibility                    | Search eventual, checkout strong source validation | Version index, rebuild and alias switch                  | Partition indexes and tune relevance        | Index lag and operational cost                                    |
| 5. Why reserve inventory              | Hold stock while payment is unresolved                                                            | Only conditional available stock can be held          | Local ACID reservation                             | Release on cancellation/expiry                           | Short transactions                          | Holding stock lowers sell-through during provider incidents       |
| 6. Prevent overselling                | Conditional update and DB checks                                                                  | on_hand >= reserved                                   | READ COMMITTED recheck predicate                   | Rollback whole checkout                                  | Stable offer lock order                     | Hot products serialize                                            |
| 7. Last item                          | Two updates contend on stock row                                                                  | Only one success                                      | Row update serialization                           | Loser gets 409                                           | No distributed lock service                 | Fairness not guaranteed                                           |
| 8. Cart versus reservation            | Cart is intent; reservation is committed workflow hold                                            | Cart promises no stock                                | Durable cart, later authoritative stock            | Requote/retry unavailable item                           | No inventory write per cart edit            | Customer may lose item before checkout                            |
| 9. Checkout design                    | Immutable quote, atomic order/reservation, async capture                                          | No client monetary authority                          | Two local transactions around provider call        | Durable orchestration/compensation                       | Return pending quickly                      | Completion latency includes provider and worker                   |
| 10. Checkout idempotency              | Customer/key unique; quote unique; payload equality                                               | One order within scope                                | Customer cart row lock + DB uniqueness             | Replay same order after lost response                    | Same-customer requests serialize            | Keys must be retained by client                                   |
| 11. Duplicate charges                 | Stable order UUID provider key                                                                    | One supported provider capture per key                | Provider ledger independent commit                 | Lookup ambiguous outcome                                 | No new key on retry                         | Real provider must support contract                               |
| 12. Payment timeout                   | Treat as ambiguous, never as definite decline                                                     | Avoid second key charge                               | Local pending until provider evidence              | Bounded retries then manual                              | Lease outside network call                  | Stock can remain held; real adapter absent                        |
| 13. Duplicate webhooks                | Verify signature and unique event inbox                                                           | No repeated local effect                              | Inbox + completion local transaction               | Redelivery after rollback                                | Provider lookup for hints                   | Retention/replay window must be managed                           |
| 14. Why Saga                          | Provider and DB cannot share ACID                                                                 | Recoverable financial/stock transitions               | Durable step state, local ACID                     | Compensate with refund                                   | Bounded workers                             | Compensation asynchronous and imperfect                           |
| 15. Orchestration versus choreography | Orchestration owns checkout decisions; choreography for secondary effects                         | Central guarded transitions                           | Coordinator persisted locally                      | Lease takeover/manual state                              | Easy to inspect critical path               | Coordinator coupling; events better for independent notifications |
| 16. Transactional outbox              | State and event insert in same transaction                                                        | No committed order without intended event             | Local inbox delivery atomic                        | Replay event ID                                          | SKIP LOCKED bounded batches                 | External transport remains at least once                          |
| 17. Recover partial checkout          | Claim due durable workflow and lookup same provider key                                           | Resume without duplicate capture                      | Guarded order/payment states                       | Periodic reconciliation plus admin retry                 | Batch 16                                    | Manual handling after eight attempts                              |
| 18. Payment after reservation expiry  | Cancel and compensate; never reacquire stock implicitly                                           | No overselling or cancelled reconfirmation            | Order lock handles expiry/complete                 | Queue idempotent refund                                  | Async refund latency                        | Customer can be charged temporarily                               |
| 19. Reliable compensation             | ACTIVE-only release, one cancellation state transition                                            | No double restock/release                             | Order lock and local inventory transaction         | Retry same step key                                      | Bounded small transactions                  | Physical stock corrections require audit                          |
| 20. Partial shipments                 | Separate seller groups and per-line shipments                                                     | Delivered only when all lines delivered               | Order lock protects cancel/ship                    | Remaining lines stay partial                             | Independent seller progress                 | Partial quantity in one line absent                               |
| 21. Cancellation after capture        | Cancel only unshipped, restock and reserve refund                                                 | No shipping cancelled order                           | Order lock with shipment check                     | Refund worker                                            | No provider call inside cancel TX           | No per-line cancellation after first shipment                     |
| 22. Duplicate refunds                 | Unique business operation key plus pending budget                                                 | Refund sum <= captured                                | Order then payment locks                           | Provider same-key retry                                  | Small indexed refund lookups                | Manual/ambiguous refunds continue consuming budget                |
| 23. Coupon limits                     | Conditional used counter and customer redemption unique                                           | Never exceed max_uses                                 | Coupon update same order TX                        | Rollback loser                                           | Popular coupon row contention               | Cancelled uses not auto-restored                                  |
| 24. Multi-seller checkout             | One marketplace order, multiple seller groups                                                     | All initial reservations succeed or none              | Single DB atomic acceptance                        | Rollback then per-seller later fulfillment               | Sorted inventory locks                      | Cross-service version requires Saga reservations                  |
| 25. Suspension and active orders      | Block new checkout/shipping; operator resolves                                                    | No new suspended seller acceptance                    | Seller status lock at acceptance                   | Restore/cancel unshipped with audit                      | Simple current-policy checks                | Automated rescue and payout policy absent                         |
| 26. Redis                             | Optional category cache-aside, durable carts in DB                                                | Cache failure never changes price/stock correctness   | TTL/eventual cache                                 | Bounded timeout, DB fallback                             | Reduces repeated category reads             | Hot-key coalescing and global caches deferred                     |
| 27. Authoritative prices              | Quote source prices; compare at checkout                                                          | No client total injection                             | Immutable snapshots with DB offer lock             | 409 on changed price                                     | Integer arithmetic                          | Tax/shipping live engines absent                                  |
| 28. Flash sales                       | Admission plus DB conditional reservation                                                         | Admission is not purchase guarantee                   | Stock authority remains DB                         | 429 backpressure                                         | 8 checkout slots per instance               | Waiting room/global fairness deferred                             |
| 29. Avoid flash-sale DB overload      | Bound checkout concurrency and connection pools                                                   | Fail before unbounded queue growth                    | No reservation for rejected request                | Retry same key after backoff                             | Upstream DB-wide budget required            | Per-instance limits insufficient alone                            |
| 30. Idempotent consumers              | Persist eventID/consumer inbox                                                                    | No repeated effect within retained dedup scope        | Inbox and side effect share TX                     | Replay same ID                                           | Indexed unique inbox                        | Kafka consumer implementation deferred                            |
| 31. Out-of-order events               | Treat payment webhook as hint; source state lookup                                                | No state regression                                   | Authoritative provider/source reads                | Version-gate future external consumers                   | Partition by aggregate                      | Aggregate version envelope not implemented                        |
| 32. Shard orders                      | Customer/home-region routing and time partitions                                                  | Single owning shard                                   | Local order atomicity                              | Directory/fenced failover                                | Archive immutable old orders                | Cross-seller stock may span shards; redesign Saga first           |
| 33. Hot product                       | CDN read cache, checkout admission, ownership partition                                           | DB final stock predicate                              | Read hints eventual                                | Backpressure and retry                                   | Serialized hot-row writes unavoidable       | Partition stock allocations only with authoritative ownership     |
| 34. Multiple regions                  | Regional browse, home-region commerce writers                                                     | No concurrent unfenced ownership                      | Catalog eventual; stock owned                      | Active-passive DR first                                  | Local reads reduce latency                  | Cross-region checkout longer and less available                   |
| 35. Cross-region inventory            | Disjoint region/warehouse allocations or consensus                                                | No async counter illusion                             | Strong per-owned-allocation                        | Fence old owner before failover                          | Local ownership scales                      | Allocation transfer needs coordinated protocol                    |
| 36. Provider reconciliation           | Compare local payment to provider by stable key                                                   | Captured/cancelled creates refund                     | Evidence-driven monotonic local update             | 60s bounded scan and manual                              | Indexed mismatch queries needed at scale    | Disputes/external refunds not covered                             |
| 37. Test financial correctness        | Real PostgreSQL constraints/concurrency and durable provider replay                               | Assert one charge/refund key and limits               | Independent provider/local transactions            | Crash-boundary and contradictory webhook tests           | Small deterministic datasets                | No live provider/chaos/settlement evidence                        |
| 38. Benchmark checkout                | Fixture quotes, distinct identities, isolated stock and generator                                 | Audit overselling/duplicates after load               | Measure accepted versus confirmed separately       | Record errors/rejections and recover workflows           | k6 target-rate matrix                       | No target-scale measurement claimed                               |
| 39. Health metrics                    | HTTP/JVM/pool plus saga/refund/outbox/admission metrics                                           | No high-cardinality business IDs as labels            | Metrics observational only                         | Alerts link to reconciliation runbook                    | Histograms/gauges cost controlled           | Some domain metrics still absent                                  |
| 40. Amazon scale changes              | Partition ownership, CDN/search read models, independent domain services                          | Preserve inventory/payment contracts while extracting | Sagas replace cross-context DB transactions        | Regional DR, schema governance, automated reconciliation | Benchmark each bottleneck                   | Large staffing/cost; baseline cannot scale by replicas alone      |
